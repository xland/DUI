# DUI 架构总纲

> 状态：草案 v0.1 — 待讨论确认。

## 1. 定位

仅 Windows 的 GUI 框架。硬性目标按优先级排序：

1. **功能完备度** —— 能力覆盖优先，不为体积牺牲核心功能。
2. **内存占用低** —— 每窗口开销小、热路径零分配、文本/图集等缓存有明确上限。
3. **性能好** —— 低 CPU 占用、支持可变刷新率、缩放与滚动流畅。
4. **体积小** —— 交付物（静态库）尺寸小，链接进应用后的增量为重要指标。

**无依赖**为硬性约束（不参与排序）：不引入任何第三方库，只依赖操作系统自带组件（d3d11 / dxgi / dwrite / dcomp / user32 / kernel32 等）。

当各项冲突时的默认取向：**功能完备度 > 内存 > 性能 > 体积**。

### 2.2 能力清单（MVP）

- 窗口（含自定义标题栏、圆角、阴影）
- 常用控件：容器、按钮、文本、编辑框、滚动视图、列表（虚拟化）
- 布局、样式、主题
- 文本排版（含字体回退、复杂脚本）
- 图片显示
- 动画
- 高 DPI（Per-Monitor）

## 3. 设计原则

- **显式优于隐式**：对象生命周期、所有权、失效（invalidate）由调用方明确表达，框架不做隐式缓存失效扫描。
- **批量化**：所有绘制先收集成显示列表，再一次性光栅化，避免逐元素 Draw Call。
- **热路径零分配**：消息处理、布局、绘制主循环内不做堆分配；内存从预分配池/竞技场获取。
- **可裁剪**：按功能编译期开关（文本/图片/动画/无障碍…），未启用模块不进入二进制。
- **不追求通用**：不为极低概率场景写容错，不为一次性功能搭抽象层。

## 4. 非目标

- 跨平台（不抽象 Linux/macOS，不为未来跨平台预留接口层）
- 内置浏览器 / WebView
- 设计器 / 可视化编辑器
- 脚本语言绑定（如 Lua/JS）

> 无障碍（UIA）、SVG、富文本编辑：待定，见 ADR-017。
