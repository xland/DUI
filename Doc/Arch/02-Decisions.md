## ADR-003 文本光栅化方式

| 方案 | 影响 | 说明 |
| --- | --- | --- |
| **每缩放档 Alpha 图集**（建议起步） | 体+++ 复+++ | `CreateGlyphRunAnalysis` + `CreateAlphaTexture` 直接得到灰度/子像素位图；代码最少。代价：每个 (字号 × 缩放档) 一份图集，缩放档多时内存上升，非档位缩放会糊 |
| 轮廓三角化 + 解析式 AA | 体-- 复--- | `IDWriteFontFace::GetGlyphRunOutline` 取轮廓 → 三角化 + 覆盖像素着色；无级缩放质量最高，但需要完整 tessellator |
| SDF 图集 | 体○ 内++ 性○ 复○ | 每字形仅需一份小尺寸 SDF，任意缩放与旋转都清晰，但需要距离场生成代码（约数百行） |

**已定：Alpha 图集 + 缩放变化时重新光栅化。**

- 接口抽象为"按 (字体/字形, 像素尺寸) 取字形位图"，图集带容量上限与 LRU 淘汰。
- DPI / 字号 / 变换缩放均视为**离散事件**：按新尺度重新光栅化并更新缓存，不做跨尺度复用采样（复用才糊）。
- 超大字号可退化为轮廓绘制避免位图过大（阈值实现时定）。
- 行业对照：Qt Widgets、Skia/Avalonia（曾有 SDF 路径后移除）、Direct2D/WinUI3 均为此路线；SDF 是 Qt Quick / 游戏引擎的连续缩放方案，DUI 未来若出现画布类无级缩放需求再引入。

另需确定（待定）：是否支持子像素（ClearType）——子像素与"任意合成/半透明"冲突，倾向只做灰度 AA。

## ADR-004 排版自己做到什么程度

| 方案 | 影响 | 说明 |
| --- | --- | --- |
| **IDWriteTextLayout 直接用** | 体+++ 复+++ | 免费获得换行、双向、复杂脚本、字体回退；控制力弱（自定义换行策略、行距微调受限） |

## ADR-007 语言特性开关

| 项 | 草案建议 | 理由 |
| --- | --- | --- |
| 异常 | **已定：关闭**（`/EHsc` → `/EHs-c-`） | 见 7.1 分析 |
| RTTI | **关闭**（`/GR-`） | 控件类型用自定义 TypeId（整数）而非 `typeid` |
| STL | **已定：边界用标准库、内核自研** —— 公开 API 接受 `std::vector` / `std::string_view` 等；框架热路径内部用自研 arena / 小容量容器 | 开发体验优先：不让开发者换一套容器；体积代价只落在边界，模板实例可控 |
| 错误传递 | **已定（随异常关闭联动）**：内部用轻量 `Result<T,E>`（或 `bool` + out 参数），仅在初始化阶段保留详细信息 | 异常已关闭，错误码是唯一通道 |
| 多线程 | UI 单线程 | 引用计数用非原子，省体积与开销 |

### 7.1 异常：为什么关闭（**已定**）

**收益**

1. **体积**：x64 异常的 unwind 信息（`.pdata`/`.xdata`）+ 每个可能抛出点的着陆垫代码，通常带来 5–15% 二进制增量，对"体积小"直接有效。
2. **控制流显式**：开异常后任何函数都可能在任意调用点隐式跳走，与"显式优于隐式"（00-Overview §3）冲突；消息/布局/绘制路径的正确性更易推理。
3. **错误模型匹配**：底层全是 Win32/HRESULT 错误码；框架内可预期错误集中在初始化与资源加载，`Result<T>` / `bool` 足够；程序员错误用断言而非异常。
4. **边界简单**：库不抛异常 → 用户回调边界无需 try/catch 屏障，用户可自由选择错误策略。
5. **生态对照**：Chromium、Google C++ 风格、多数游戏引擎与嵌入式 GUI 均禁用或避免异常。

**代价（需接受）**

1. 构造函数无法报错 → 资源类用 `Create()` / `Init()` 工厂或两阶段初始化。
2. STL 受限（`bad_alloc`、`at()`、`stoi` 等），与"STL 待定"项耦合——启用也只限不抛场景。
3. C++/WinRT 不可用（见 ADR-022 D1 的评估前提）。
4. 协程可用，但 `unhandled_exception` 只能 `terminate`（见 [07-Threading.md](./07-Threading.md) §4.2）。
5. OOM 策略：分配失败直接 abort（GUI 惯例），热路径由 arena 预分配兜底。

**反方案（保留异常）**：构造函数失败表达自然、STL 全量可用；代价是体积增加、回调边界需异常屏障、控制流隐式化。

> **联动生效**：异常已定关闭，以下结论随之生效 —— `Result<T>` 错误传递（03/07）、不用 C++/WinRT（07 D1）、`Create()`/`Init()` 构造模式（全局 API 风格）。RTTI 仍为草案，待拍板。

## ADR-010 窗口形态

| 方案 | 影响 | 说明 |
| --- | --- | --- |
| **普通 HWND 不透明**（建议默认） | 体+++ 性+++ 复+++ | Flip Model 交换链，性能与延迟最优；圆角/阴影需另想办法 |
| 普通 HWND + 自绘圆角（利用 DWM 区域裁剪或自绘到不透明背景） | 体++ 性++ | 由 DWM 处理圆角时需走非公开 API，需评估 |
| `WS_EX_LAYERED` + `UpdateLayeredWindowIndirect` | 性-- | 走 GDI 合成路径，大尺寸窗口下内存拷贝开销明显 |
| DirectComposition（dcomp.dll） | 体- 性++ 复- | 系统组件，属"无依赖"；可拿圆角/阴影/合成动画，但引入视觉树与 IDComposition 复杂度 |

**已定：DirectComposition（dcomp.dll，系统组件）承载窗口。** 圆角/阴影/透明为早期必须能力，故不走普通不透明 HWND 与 Layered Window 路线，直接采用 DComp 视觉树 + D3D11 交换链内容。代价（视觉树管理复杂度、少量内存）在当前优先级（开发体验优先）下可接受。
随之需确定（待定）：圆角/阴影由 DComp 特性提供还是自绘到透明像素；每窗口一个 DComp Device 还是进程级共享。

**已定（补充）：窗口形态清单 —— 普通 + 无边框 + Popup（菜单/下拉）+ 模态对话框；MDI 不做。**（其余窗口决策延后到 12-Windowing 逐条定）

## ADR-014 DPI 与缩放（已定）

- DPI 感知级别：**Per-Monitor V2**（基线 1703，与 ADR-009 对齐，不再下探）。
- 内部单位：全部使用 DIP（1/96 英寸），物理像素只出现在输入入口与呈现出口两个边界。
- 缩放档位：整数档优先；非整数档走**自绘**（几何按 `dip × scale` 直接计算，字形按像素尺寸离散光栅化），**不依赖系统位图缩放**。
- 用户级 UI 缩放（P2）：与系统 DPI **相乘**，不采用覆盖。

> 落地设计（三套坐标、`WM_DPICHANGED` 时序、各子系统响应、高保真纪律、`pixelSize` 取整与多倍图约定）见 [12-Windowing.md](./12-Windowing.md)。

## ADR-016 工程结构

**已定（工程已创建）**：`DUI.slnx` 下两个工程 —— **DUI（库）+ Samples（示例）**，将来可能增加更多子工程。源码按 `Core / Platform / Graphics / Text / UI / App` 分层。

```
DUI.slnx                 解决方案
DUI/                     库工程（静态库 .lib）
  Core/ Platform/ Graphics/ Text/ UI/ App/
Samples/                 示例工程（可按示例数量增子工程）
```

**已定：交付形态为静态库。** 链接器自动裁剪未引用代码，未启用模块不进二进制，最利于体积与集成。

**编译基线统一由 `Build/DUI.props` 提供**，库工程与示例工程共同 import —— 避免 `/MT` 与 `/MD` 混用触发 `LNK2038`。

**Samples 工程已建**（`Samples/Samples.vcxproj`，控制台子系统，将来可增子工程）：内含**三栏阅读器示例**（左菜单 / 中列表 / 右正文），同时充当"目标 API 的可执行规格"。现状：`DUI.lib` 可构建；示例因缺 `DUI/DUI.h` 暂不可编译（预期，待库实现）。

## ADR-018 开发者界面编写方式

**已定：纯 C++ 直接编写界面，不提供 XAML / HTML / CSS 等声明式描述语言。**

- 界面 = C++ 代码组合控件（构造 → 设置属性 → 添加子元素）。无运行时 UI 描述解析器：省体积、省启动开销，界面结构的类型安全由编译期保证。
- 简化写界的手段是**提供大量可高度定制的控件**，而非描述语言。定制点分层：
  1. 属性 / 样式覆盖（颜色、圆角、间距、字号等）
  2. 自定义绘制钩子（接管或追加绘制）
  3. 布局参数（见 ADR-006 的布局模型）
  4. 继承派生新控件
- **提供**链式 builder：`Style` 构造期与控件属性/事件侧（返回 `Element&`）均提供，见 [03-Style.md](./03-Style.md) §6 与 [06-Events.md](./06-Events.md) D3。
- 待定：主题/资源是否需要运行时文件形态（[03-Style.md](./03-Style.md) D4 建议 MVP 用编译期常量 + 运行时替换接口）。

## ADR-019 样式系统模型

需求：框架自带样式规则（`backgroundColor` / `color` / `textAlign` / `fontSize` …），且样式可在界面元素间复用。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 属性存储 | **稀疏 `{PropId, Value}` 数组** | 只存设置过的；"共享 + 派生 + 局部覆盖"本质是表达差异集，与稀疏结构同构 |
| `Style` 可变性 | **不可变、可共享、可派生；名字可选**（具名仅为注册表键 + 调试标识，不参与匹配） | 复用不产生拷贝；不可变才敢被 N 个元素共享；默认匿名免去起名负担与静态初始化期驻留 |
| 解析结果 | **混合**：继承属性走遍历期 `StyleContext` 栈，非继承属性用按需 `Style::Resolve`（ADR-024） | 遍历内零开销；遍历外（事件/命中测试/动画）也需要读路径，按需上溯足够便宜 |
| 复用机制 | 共享 `Style` + 派生差异 + 属性继承，**不做选择器** | 控件内置默认 `Style` 已等价于类型选择器，零成本 |
| 主题 | MVP 编译期常量 + `SetTheme()` 整体替换 | 不做文件解析，控体积 |
| 失效粒度 | 属性元数据带 `Layout` / `Text` / `Paint` / `Inherit` 标志，按标志标脏 | 改颜色不触发重排（R7） |

**已定：按上表。** 完整设计见 [03-Style.md](./03-Style.md)，其中 D1–D4、属性清单、状态变体、待确认项仍需逐条确认。

## ADR-020 动画系统

需求：支持类似 CSS 的动画设置 —— 过渡（transition）与关键帧动画（keyframes）。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 接入方式 | 动画作为样式级联第 1 层"动画值源"，`transition` / `animation` 为普通样式属性 | 复用样式系统的级联、失效与状态变体联动，不另起炉灶 |
| 双机制 | 过渡（基值变化被动触发）+ 关键帧（显式启动） | 对应 CSS transition / @keyframes，覆盖声明式与命令式两类需求 |
| 中断语义 | 新动画从**当前显示值**起播，同 (元素, 属性) 唯一 | hover 快速进出不跳变（R2） |
| transform | 引入 `translation` / `scale` / `rotation`（Paint 级，不参与布局） | 无它则位移动画每帧重排；需同步作用于命中测试 |
| 驱动 | MVP：UI ticker（帧循环）；P2：窗口级 DComp 动画 | 元素级合成需保留合成树，近期不做；窗口级为低成本优化 |
| 缓动 | 预设 + 自定义贝塞尔（LUT 常量表）；Spring 列 P1 | 零分配、够用；中断语义已为 spring 预留 |
| 可裁剪 | `DUI_ENABLE_ANIMATION`（既定约定） | 关闭后动画槽/tick/API 全部不进二进制 |

**已定：按上表方向。** 完整设计见 [05-Animation.md](./05-Animation.md)，其中 D1–D4、池容量策略、回调重入约束等仍需逐条确认。

## ADR-021 输入与事件

需求：开发者能方便地为界面元素绑定事件处理程序，并保留底层事件控制能力。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 绑定形态 | `btn->OnClick(fn)` / `OnClick(this, &T::Method)` / `AddHandler(id, h)` 三形态 | 语义糖保便利（R1），底层入口保完整（R3） |
| 处理器存储 | `Handler`（fn 指针 + ctx 指针，16 B）直调；`SmallFn` 捕获闭包列 P1；不用 `std::function` | 分发热路径零分配零虚表；注册期构建才发生 |
| 路由 | **冒泡 + 捕获（隧道）双阶段**（MVP 即提供）+ `handled` + 直达事件；处理器以 `Phase` 参数声明阶段，事件 ID 单表不成对 | 拦截/预判是常见需求；单表 + Phase 参数避免事件 ID 成对膨胀 |
| 指针捕获 | `SetPointerCapture()`，拖拽基础 | 抬起前 Move/Up 直达捕获者 |
| 焦点 | 唯一焦点 + Tab 链（树序 + `focusable`/`tabStop`）；焦点态自动写 `State::Focused` 联动样式 | 焦点视觉零成本接入样式系统 |
| 分发期改树 | 允许修改/标脏；销毁走延迟删除队列 | 不把生命周期复杂度转嫁给开发者 |
| 生命周期 | 处理器随元素销毁自动摘除；ctx 裸指针由开发者负责，weak token 列 P2 | 简单显式，反馈频繁再托管 |
| 链式 API | `OnClick` 等返回 `Element&`，**收敛 ADR-018 悬案：提供链式** | 事件绑定是链式最高价值场景 |

**已定：按上表方向。** 完整设计见 [06-Events.md](./06-Events.md)，其中 D1–D5、语义事件清单、Click 合成参数等仍需逐条确认。

## ADR-022 线程与异步

需求：开发者能方便地在自己的代码（如事件处理函数）中切到子线程处理业务，并方便地回 UI 线程更新界面。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| WinRT 引入 | **不引入其实现，自研精简 Dispatcher；API 按易用性自定，不刻意对齐 WinRT 命名** | C++/WinRT 全面依赖异常，与 ADR-007（已定）冲突；裸 COM 需背负 RoInitialize/apartment，收益不抵复杂度 |
| 双通道 | UI `Dispatcher`（PostMessage 唤醒，帧循环排空）+ 固定线程池（min(4, 硬件并发)） | 与消息泵零摩擦；行为可预期 |
| 风格 | **协程风格为体验主路径**（`dui::Task<T>` + `co_await dui::Background()` / `dui::Foreground()`，与回调风格平级，建议 P0 落地最小集）；回调风格并存 | R3；协程切换点为命名空间内函数，调用点即"动作"；协程体内不用异常，错误走 `Result<T>`（对齐 ADR-007） |
| 线程规则 | 后台只碰纯数据，碰 UI 必经 `ui.Post` 回投 | 不破坏 ADR-012 单线程 UI |
| 生命周期安全 | 取消令牌；`Lifetime` 安全回投（元素销毁自动作废，联动 ADR-021 D5） | 消除"回调时界面已销毁"悬挂 |
| 队列上限 | 固定池（1024），满则丢最旧 + 告警 | 与动画池策略一致，拒绝无限队列 |

**已定：按上表方向。** 完整设计见 [07-Threading.md](./07-Threading.md)，其中 D1–D5、并发度、组合子范围等仍需逐条确认。

## ADR-023 文本能力与富文本编辑器

需求：① 文字渲染、排版能力尽可能丰富；② 框架将来提供富文本编辑器控件（所见即所得，类似 Web 富文本编辑器）。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 能力分层 | L1 排版引擎（无状态）/ L2 富文本文档模型 / L3 编辑器控件 | 各层可独立测试与裁剪；控件阶梯 Label → TextBlock → TextBox → RichEdit |
| 排版基座 | `IDWriteTextLayout` **段落级**使用 + 段落缓存/失效（确认 ADR-004） | 免费获得换行/BiDi/复杂脚本/回退/命中测试/内联对象 |
| 富文本属性 | **内容属性，不进样式系统**（ADR-019）；文档默认值由元素样式注入 | 内容样式随文本走（复制/序列化），元素样式管外观，二者解耦 |
| 编辑数据结构 | 段落 = 文本 + 属性区间表；MVP run 数组，piece table P2 | 简单优先，接口不变可后换 |
| RichEdit 排期 | 控件 P2；L1 能力清单与 L2 数据结构**自现在起预留** | "将来提供"= 交互后置、能力先行，避免返工 |
| 剪贴板/序列化 | MVP 纯文本；内部格式 P2；HTML/RTF 导入导出 P2 且可裁剪 | HTML 解析体积可观，不用不链接 |
| 属性集与范围 | **已拍板**：核心可支持的均列入目标 —— 背景高亮、链接（P1）、基础竖排（P2）；需自实现的（上下标）与编辑器周边（拼写检查/协同编辑）先不实现 | 拍板原则：不支持的先不实现，其他都进目标 |

**已定：按上表方向。** 完整设计见 [11-Text.md](./11-Text.md)（§9 已拍板记录），文本选择的完整程度仍待定。

## ADR-024 属性主表与运行时读路径

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 属性清单归属 | **集中到 [15-Properties.md](./15-Properties.md)，唯一事实来源**；03/04/05/11 只写消费与语义 | 三处清单重复且出现"在 03 之外新增却重复列 `display`"的矛盾；属性表是首份要写的代码 |

| 一致性 | 两条路径**均经"元素活动动画链表"**查级联第 1 层，同帧结果必须一致 | 避免两套解析逻辑 |

**已定：按上表。** 细则见 [15-Properties.md](./15-Properties.md) §5。

## ADR-025 跨线程对象所有权与引用计数

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 可引用对象 | **仅 UI 线程持有**（元素/样式/纹理/字体/资源） | 与 ADR-007"引用计数非原子"自洽，省体积 |
| 工作线程职责 | 只处理**纯数据**（字节、解码后的位图内存），不得持有任何带引用计数的对象 | 消除数据竞争 |
| 跨线程传递 | **move 所有权**（UI → 工作线程 → UI） | 无锁、无原子计数 |
| 违例检测 | Debug 下 `AssertUiThread()` + 对象构造期线程校验 | 尽早暴露误用 |

**已定：按上表。** 与 ADR-022 的双通道模型配套（[07-Threading.md](./07-Threading.md) §3.1）。

## ADR-026 字符串编码约定

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| API 与内部编码 | **统一 UTF-16**：`const wchar_t*` / `StringView`（UTF-16）；字面量用 `L"..."` | DWrite、Win32 W 系列、剪贴板（`CF_UNICODETEXT`）、IME 全是 UTF-16，边界零转码 |
| UTF-8 的位置 | 仅在外部边界（文件、网络、JSON、日志），经 `String::FromUtf8` / `ToUtf8` **显式**转换 | 不让两种索引空间渗进内部 |
| 索引语义 | 文本位置/范围/命中测试一律 **UTF-16 code unit**，与 `DWRITE_TEXT_RANGE` 一一对应 | 富文本编辑器的选区、光标、撤销栈前提；避免"字节偏移 ↔ 码元偏移"映射表与切半字符的 bug |
| 源文件编码 | `/utf-8` 为**强制前提**（已落地） | 否则 `L"中文"` 按系统代码页解读会乱码 |
| 内存 | 中文界面 UTF-16 更省（2 B/字 vs UTF-8 3 B/字） | 纯 ASCII 时相反，量级可忽略 |

**已定：按上表。** 与 [11-Text.md](./11-Text.md) §4 的"模型内部 UTF-16"一致；示例与文档片段已统一改为 `L"..."`。
