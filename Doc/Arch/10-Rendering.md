# 渲染

> 状态：草案 v0.1 — **渲染主路径已定案**（§9 结论记录）；阴影已落地（box-shadow 子集，Shape 批 kind=3 的 SDF 衰减带，无纹理/离屏）；模糊、离屏缓冲、任意形状投影（drop-shadow）等 P1/P2 项随实现推进补充。
> 需求来源：保留模式 + 脏区（ADR-005）、按需呈现（"没有失效就没有工作"）、高保真（[12-Windowing.md](./12-Windowing.md) §7.1）、批量化（[00-Overview.md](./00-Overview.md) §3）。
> 相关：[01-Layering.md](./01-Layering.md) §3（帧生命周期）与 Graphics 模块清单、[02-Decisions.md](./02-Decisions.md) ADR-001（D3D11+DXGI）/ ADR-003（字形光栅）/ ADR-005（保留模式）、[03-Style.md](./03-Style.md) §7（失效表）、[05-Animation.md](./05-Animation.md) §7、[12-Windowing.md](./12-Windowing.md)。

## 1. 需求

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| R1 | 按需工作 | 无脏区且无动画时：不收集、不光栅、不 Present，CPU/GPU 归零 |
| R2 | 局部代价 | 改一个颜色只付出"重绘该元素"量级的成本，不触发全窗重排 |
| R3 | 批量化 | Draw Call 数与元素数量解耦；同图集/同材质的矩形合并为尽可能少的批 |
| R4 | 高保真 | 预乘 Alpha 全程一致、描边像素对齐、灰度 AA（整像素覆盖率直出，见 [12-Windowing.md](./12-Windowing.md) §7.1） |
| R5 | 热路径零分配 | 收集/排序/顶点生成全程走 Arena 与环形缓冲，无堆分配 |
| R6 | 可裁剪 | 文本/图片/动画关闭后，对应渲染路径不进二进制 |

## 2. 管线总览

与 [01-Layering.md](./01-Layering.md) §3 的帧生命周期对齐，渲染侧的细化数据流：

```
[失效]  属性 / 状态 / 样式 / 布局变更 → 产出脏矩形（帧末合并，见 §4）
   ↓ 有脏区或有活动动画？
[收集]  Arena 重置 → 遍历可见元素树（视口 + 裁剪剔除）→ 显示列表（§3）
   ↓
[排序]  不透明指令按"材质 → 图集"分组前置；半透明指令保持 Z 序（画家算法）
   ↓
[批合并] 同批次写顶点环形缓冲 → 合并为最少 Draw Call（§6）
   ↓
[光栅]  顶点统一乘 scale 矩阵（DIP → 物理像素）→ 片元着色（§6.2）
   ↓
[呈现]  Present(0, 0) 立即提交（ADR-013；本帧无脏区则不调用，见 §5）
```

入口判定"**有没有脏区**"在帧生命周期的最前端：它决定这一帧是否存在，而不是决定这一帧里省多少事（见 §5 的 FLIP 约束）。

## 3. 显示列表

**D1 构建策略：每帧全量重建（已定，MVP）。**

| 方案 | 体 | 复 | 说明 |
| --- | --- | --- | --- |
| **全量重建**（MVP） | ○ | ++ | 有脏区时重置 Arena、遍历整棵可见树重新收集指令；失效模型只有一套（Style/布局的失效表），无第二套缓存失效 |
| 按元素分段缓存 | + | -- | 每元素缓存自己的指令段，脏元素只重建自己的段；省收集，但引入与样式失效正交的第二套失效管理，且段边界与层/裁剪耦合 |

选择依据：收集本身是纯 CPU 内存写，一个 1000 元素的界面全量重建 < 0.1 ms 量级；而分段缓存省下的正是这部分。**用 profile 说话**：只有当 P95 收集耗时 > 0.5 ms、且占当帧 CPU 总耗时 > 15%、连续 100 帧时才立项（双条件缺一不可，判定细节见 §9-5）。

显示列表的内容：

| 指令 | 说明 |
| --- | --- |
| `Rect` / `RoundedRect` | 纯色或渐变填充；圆角在片元着色器内按 SDF 距离裁形（§6.2） |
| `Shape` | 2D 图元：线段（胶囊）/ 椭圆 / 圆角矩形，填充与描边；SDF + fwidth AA，独立形状批（§6.1） |
| `TextRun` | 字形实例（图集坐标 + 位置），来自 Text 层排版结果 |
| `Image` | 图集/纹理引用 + 目标矩形 |
| `PushClip` / `PopClip` | 矩形 / 圆角矩形裁剪（栈式，与 `overflow` 联动） |
| `PushLayer` / `PopLayer` | 离屏层：`opacity < 1` 的子树、带 `transform` 的子树 |

层（`PushLayer`）是渲染里唯一"子树整体先画到离屏再合成"的场合，触发条件收敛为：`opacity < 1`、`transform` 非恒等。其余一律直绘，避免层爆炸。

层载体（已定）：**独立 render target + 精确尺寸池化**。

- 不进图集页：层 bounds 可达整窗大小，会打碎为字形/图标设计的图集布局；且"整层合成后再采样"在图集页上有相邻内容渗色（bleed）问题，无解。
- 池化：按精确 `(宽, 高)` 匹配 + LRU 上限 **16 个**。层 bounds 在动画期间基本稳定，精确匹配命中率远高于 2 的幂档位；超上限淘汰最久未用。
- 失效：层内任何元素脏 → **整层重绘**（不做层内脏区追踪）；层 bounds 变化 → 换 RT。
- 深度防护：层嵌套 ≤ **4**，超出在 Debug 下断言 —— 嵌套过深说明界面结构有问题，应在设计层解决而不是让渲染硬扛。

内存：显示列表、排序缓冲、顶点全部从窗口 Arena 分配，帧末整体重置（[01-Layering.md](./01-Layering.md) §4），热路径零分配（R5）。

## 4. 脏区

脏区的职责在 MVP 下是**决定"这一帧是否存在"以及"将来限定光栅范围"**，不是限定本帧像素更新（原因见 §5）。

### 4.1 产出

每条失效路径换算为一个矩形（03-Style §7 的失效表 → 矩形）：

| 来源 | 矩形 |
| --- | --- |
| `Paint` 类属性变更 / 状态切换 | 元素当前 bounds（含 `transform` 后包围盒） |
| 元素移动 / 消失 / 滚动 | 新旧两个 bounds 的并集 |
| 文本重排版 | 受影响行盒区域 |
| 阴影 / 层 | bounds 外扩（模糊半径 + 偏移） |
| 布局变更 | 受影响子树的联合包围盒 |
| DPI / 用户缩放变化 | 全屏 |

### 4.2 合并

- 帧内先收集后合并：帧末对脏矩形列表做**一次**合并，而不是每次失效都合并。
- 合并规则（已定）：列表上限 **8** 个矩形；插入新矩形时与现有矩形求可合并对（相交/相邻则并）；超过上限或联合面积超过窗口 **50%** → 退化为单一包围盒乃至全屏。
- **贪心两两合并即止，不做最优矩形并**（那是 NP 难题的花样版本）。这两个阈值在 MVP 下只影响"进不进帧"的精度，真正生效于 P2 的离屏缓冲方案；定值原则是够用、可调、实现极简。
- 定值依据：常见交互同时产生约 3–5 个独立脏区（hover 项 + 旧 hover 项 + 提示 + 滚动条）；列表滚动一步就超限退化全屏——这正是期望行为。50% 以上时多 scissor 的状态切换成本开始超过省下的填充。
- 脏区列表本身从 Arena 分配，帧末随 Arena 重置。

## 5. 呈现策略（FLIP 交换链的约束）

**D2 核心结论：MVP 做"按需全量光栅"，不做局部像素更新。**

约束来源：交换链用 Flip Model（`DXGI_SWAP_EFFECT_FLIP_DISCARD`，ADR-001 已定方向），Present 之后后台缓冲内容**未定义**——不能假设上一帧的像素还在，因此不存在"只重绘脏区那几十个像素、其余沿用上帧"的直接做法。`Present1` 的 dirty rects 参数在 FLIP 模型下同样不受支持。

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| **按需全量光栅**（MVP，已定） | 有脏区/动画才进帧；进帧则整窗重新光栅 + Present | 简单、正确；GPU 侧一个中等复杂度界面全屏重绘远低于 1 ms，60 fps 无压力 |
| 持久离屏缓冲 + 脏区更新 + 全屏 blit | 脏区像素更新到一张常驻纹理，再整体拷入后台缓冲 | 省 GPU 光栅，但多一次全屏拷贝 + 常驻显存 + 第二套脏区管理；仅在"全量光栅成为实测瓶颈"时引入（P2） |

这个结论同时回答了 [05-Animation.md](./05-Animation.md) §7.4 遗留的问题——**动画期间不放弃脏区，但也不靠脏区省事**：动画期间 UI ticker 每帧进帧（本来就要全量光栅），脏区继续按 §4 记录，供未来的离屏缓冲方案使用。两条文档由此收敛为同一结论。

与 [12-Windowing.md](./12-Windowing.md) 的衔接：scale 变化（DPI / 用户缩放）走唯一入口 `Window::ApplyScale(scale)` → 交换链 `ResizeBuffers` + 全屏脏区，P2 的用户缩放只是再调一次它。

**后台缓冲格式（已定）：`B8G8R8A8_UNORM`。**

- DWM 合成、截图工具、远程桌面的 Windows 桌面管线以 BGRA 为惯例；保留将来与 Direct2D 互操作的路径（`CreateBitmapFromDxgiSurface` 要求 BGRA）。RGBA8 无补偿性优势。
- 用非 sRGB 的 `UNORM`（gamma 空间混合），理由与代价见 §6.2。

## 6. 批合并与光栅

### 6.1 有序显示列表与批合并（B2）

- **收集期**（`Painter`）：按元素树遍历顺序记录 `PaintCommand`（定宽 64 B：`op` / 状态槽索引 / 资源 id / 打包颜色 / 11 个参数）+ `PaintState`（DIP 空间变换 + 滚动原点）。指令不含烘焙后的窗口坐标（字形例外，见下），滚动只改状态槽；容量跨帧复用，稳态零分配。
- **坐标空间**：`Rect` / `Image` 存 DIP 原值，`Shape` 存记录期换算好的物理像素（含 origin），`Glyph` 存布局空间物理像素 —— 字形绑定当前 DPI 下光栅化的图集位图与 1/4 像素相位，故 **DPI/resize 时字形指令须整体重收集**（与浏览器按 `(device scale, font, size)` 分桶的字形缓存同理）。其余指令可跨 scale 复用。
- **状态槽**：`SetTransform` / `SetOrigin` 追加或复用状态槽，指令按索引引用。像素空间有效矩阵 `E = Translate(originPx) · xform(px) · Translate(−originPx)` 由 `Painter::StateTransform()` 统一推导，发射期与裁剪 AABB 共用。
- **发射期**（`Device::Render`）：一遍流式遍历指令，按 `op` 展开成 4 顶点写入动态 VB。顶点按**段顺序线性排布**；段 = 连续同 `op`（着色器 / 顶点格式）+ 同 `resource`（图集页 / 纹理）的指令，且**不得跨绘制单元**（scissor 是单元级），单段 quad 数受静态 IB 容量 `kMaxQuads` 限制。
- **提交**：静态 IB 是 0-based 局部 quad 索引（`q*4` 起 6 个索引）。每段把 VB 绑到自身字节起点 → `StartIndexLocation = 0`、`BaseVertexLocation = 0`，`DrawIndexed(quadCount*6, 0, 0)`；跨段只切 layout / stride / shader / SRV（相同则缓存跳过）。**不再有负 `BaseVertexLocation` 与跨单元 `quadBase`**。
- **严格 z 序**：段顺序 = 指令顺序 = 绘制顺序，故单元内严格 painter's algorithm —— 后画的图元无论属于哪一类，都完整遮盖先画者的全部内容（含文字）。半透明按序混合，不引入 depth buffer。跨单元顺序仍由单元顺序决定（scissor / 滚动原点 / 窗口级 Fixed 层仍是单元边界）。
- 顶点格式：`Vertex` 32 B、`GlyphVertex` 20 B（字形与图像共用）、`ShapeVertex` 48 B；共用一块动态 VB，容量按最大 48 B/顶点预留，上传量与段划分无关。
- **代价**：Draw Call = O(段数)，段数 ≈ 绘制序列的批切换次数（典型 UI 每个元素「背景 → 文字」交替 → ≈ 2×元素数），与 R3「Draw Call 与元素数解耦」存在张力。P1 已落地的指令级视口剔除在发射期丢掉屏外 / 被裁剪的指令（不生成顶点、不建段），段数只按可见指令计算；不变子树指令缓存与 P2 tile 脏区光栅 / 合成层继续摊薄（§8）。
- 指标：Draw Call 数、段数、顶点数纳入观测（ADR-015：以指标跟踪回归，不设硬门槛）。

### 6.2 片元着色

着色器数量刻意压到极少：

| 着色器 | 覆盖 |
| --- | --- |
| 纯色/渐变 + SDF 圆角 | `Rect` / `RoundedRect`（圆角矩形在片元内按距离场裁形，一次 draw，无 stencil） |
| SDF 图元 | `Shape`（胶囊线段 / 椭圆 / 圆角矩形，填充与描边；kind 分支求局部空间有符号距离） |
| 图集采样 | 字形（灰度 AA，DWrite 直出整像素覆盖率）、图标、图片 |
| 阴影（已落地） | `Shape` kind=3：圆角矩形 SDF + 以元素边界为中心的宽衰减带（box-shadow 子集，无纹理/离屏） |
| 后续：模糊 / 任意形状投影 | P1+，drop-shadow 需把内容离屏光栅后按 alpha 模糊 |

像素对齐（[12-Windowing.md](./12-Windowing.md) §7.1-4）在顶点生成阶段完成：描边/分割线类指令的坐标对齐到物理像素网格，文本与大面积填充不做。

**SDF 圆角矩形的抗锯齿（已定）：宽度用 `fwidth()`（屏幕空间导数），不做固定值。**

```hlsl
float w = fwidth(d);                        // 自动随 scale / transform 缩放
float alpha = 1.0f - smoothstep(-w, w, d);
```

- 固定 1 物理像素在 200% 下"过锐"（AA 宽度不足半像素，圆弧出台阶）；固定 1 DIP 在 100% 下"过糊"。`fwidth` 两者皆无，还顺带正确处理 `transform.scale` 动画期间的连续缩放；`fwidth` 是 ps_5_0 标准指令，零额外开销。
- batcher 约束：圆角矩形必须是**独立 4 顶点 quad**（实例化绘制），不得与其他几何共享三角形边 —— `fwidth` 基于 2×2 quad 差分，共享边界会出伪影。批合并本就是矩形流水线，天然满足，成文防回退。
- 例外：圆角半径 < 1px 时退化为直角矩形，该分支在 **CPU 收集阶段**做，不进 shader。

**混合空间（已定）：gamma 空间（非 sRGB render target）。**

- 样式常量按 sRGB 直觉书写，换 sRGB RT 会整体改变配色观感；与 DWM / Direct2D / 主流 Windows UI 框架一致。
- 字形 AA 直接使用 DWrite **灰度抗锯齿**输出的整像素覆盖率（`DWRITE_TEXT_ANTIALIAS_MODE_GRAYSCALE` + `DWRITE_TEXTURE_ALIASED_1x1`），管线内不做二次校正，也不对 coverage 做 gamma/对比度 S 曲线后处理（Qt Quick 6.11 / Skia 均不做；自造 S 曲线会压窄 AA 过渡带 → 发虚且颗粒）。
- 已知代价：gamma 空间的半透明混合数学上不严格（大面积低透明度叠加轻微偏色），全行业 2D UI 的通行取舍；真出现问题时局部换 sRGB RT 是后向兼容的改动。

### 6.3 裁剪

- `Clip` 栈与元素树的 `overflow` 联动：`Hidden` → `PushClip(RoundedRect)`；`Scroll` → 裁剪 + 内容偏移（不重排，04-Layout §6.1）。
- 矩形裁剪优先 scissor（零成本），圆角裁剪走片元 SDF；同一批内裁剪状态一致才可合并。
- **实现形态（M5.6 落地，M5.17 改为有序指令）**：绘制单元 = 一个 `Painter`（指令序列）+ 一个裁剪矩形（物理像素），
  `Device::Render(const DrawUnit*, uint32_t, float scale)` 按单元顺序提交；每个单元先
  `RSSetScissorRects` 再按 §6.1 的段顺序逐段 `DrawIndexed`，嵌套裁剪区域取交集。
  段不得跨单元，故单元边界仍是 scissor / 滚动原点 / 窗口级 Fixed 层的硬边界。
  - 滚动容器的内容单独成单元：`Painter::SetOrigin(-offsetX, -offsetY, scale)`
    只平移绘制坐标（布局结果不变），裁剪 = 视口 ∩ 外层裁剪；
  - 滚动条画在内容之上的父级单元（不随内容滚动）；
  - 单元顺序即 Z 序（`Painter` 池跨帧复用，稳态零分配）。收集子项分两趟：
    流内子项按树序先画，脱离文档流的 `Absolute` 后画；`UI/Event.cpp` 的命中测试
    按同样两趟倒序，保证后画者先命中。
  - **窗口级 `Fixed` 层**（04-Layout §4.3）：`Fixed` 不进当前单元，遍历时按树序原位
    记录 `FixedItem{元素, 祖先裁剪快照, 继承态}`，主树全部 `Commit()` 后在 `Finish()`
    里统一绘制 —— 每项一个单元，原点 = 窗口、变换 = 恒等、裁剪 = 祖先裁剪快照。
    因此 Fixed 可挂任意层级（含 Scroller 内部），不受祖先 transform / 滚动原点 /
    视口 scissor 影响，且盖过所有普通内容（含滚动条）。`HitTest` 在普通树遍历之前
    按同一顺序倒序命中该层；布局期 `FixedCount() == 0` 时绘制与命中两侧都整段
    短路，未使用 Fixed 的应用零额外遍历与属性解析。
  - **`Absolute` / `zIndex`（04-Layout §4.3）**：第二趟的脱离流项改由 `ZOrderedOutOfFlow()`
    提供（数据源是布局期按 CB 分组的锚点表 + 直接 Fixed 子项；按 `zIndex` 升序、
    同值按锚点顺序稳定排序），`Frame.cpp` 两处收集与 `UI/Event.cpp` 的
    `HitTestInner` / `CollectFixedLayer` 共用同一有序列表，四处顺序一致；命中倒序即
    "值大者后画、先命中"。跨中间容器提升的 Absolute 在 CB 处进入当前绘制单元，
    故沿用 CB 的滚动原点与 scissor。缓冲按递归深度分层跨帧复用（遍历逐层下传
    `depth`），热路径零分配；`UseOrderedOutOfFlow() == false` 时四处都走原两趟。

### 6.4 发射期顶点变换（Paint 级 transform，已落地）

`TranslationX/Y`（DIP）、`Rotation`（度，支点 = 元素盒中心）、`Scale`（等比）是四个普通 Paint 类属性，**不改 `Bounds()`、不重排**，标脏 `kFlagPaint`。它们由 `ElementTransform()`（`UI/StyleResolve.cpp`）合成为布局 DIP 空间的仿射矩阵 \(T(p)=c+t+M(p-c)\)，`Core::Transform2D` 提供组合 / 求逆 / DPI 共轭（`Scaled(s)`）。

- **收集**：`App/Frame.cpp` 的 `Collector` 逐元素压栈 \(T_{\text{parent}}\cdot T_{\text{child}}\)，以 **DIP 空间**矩阵下传给 `Painter::SetTransform()`（缩放共轭推迟到发射期）；恒等变换不压栈，未使用 transform 的元素零额外开销。
- **发射**：`Device::Render` 遍历指令时按 `Painter::StateTransform(state, scale)` 推导有效矩阵 \(E=\text{Translate}(o_{px})\cdot T_{px}\cdot\text{Translate}(-o_{px})\)，其中 \(T_{px}\) 与滚动原点无关，只有 `E` 依赖原点 —— 嵌套 `Scroller` 切换原点时无需重算祖先变换链。`FillRoundedRect` / `AddGlyphQuad` / `AddImageQuad` / `PushShapeQuad` 四类 `PaintOp` 的顶点生成都过 `E`；变换烘进顶点，故同一 `Painter` 可承载多个不同变换的元素，无需拆分绘制单元。
- **SDF 不变**：`Vertex.lx/ly`、`ShapeVertex` 的局部坐标与形状参数、字形 `uv` 全部保持原值。旋转是等距变换，片元在局部空间求出的距离场梯度模长仍为 1 → 圆角 / 描边 / 1px AA 过渡带都不失真；等比缩放只让过渡带变成 `s` px（略糊），这是不做非等比缩放的硬理由。**着色器、顶点格式、输入布局、VB/IB 编排全部未改**。
- **命中测试**：`UI/Event.cpp` 沿祖先链逐层施加 `T_e⁻¹`，等价于整体 \(T^{-1}\)；`Scroller` 的滚动条 / 视口 / `+off` 换算都用逆变换后的局部坐标。`Scale → 0` 时矩阵不可逆，该元素视为不可命中。
- **裁剪**：scissor 天然轴对齐。`BeginClip` 取变换后内容矩形四个角点的 AABB 再与外层裁剪求交；滚动容器视口保持窗口空间矩形、不随容器 transform 旋转。
- **边界**：字形按 ADR-006 在离散尺度光栅化，连续 `Scale` 动画下是被线性拉伸的图集位图（放大略糊）；`PointerEvent::pos` 仍是客户区绝对 DIP，旋转的交互文本框光标/选区定位列为后续项；平移不会扩展 `Scroller` 的可滚动范围。**带 transform 的 `Scroller` 且滚动偏移非零时**，内容命中测试仍沿用原有的 `+off` 平移换算（未把滚动纳入变换链），视口 scissor 也保持窗口空间轴对齐，属已知限制。

> 本文 §3 的 `PushLayer/PopLayer`（`opacity<1` / 带 transform 的子树走离屏层）、§6.2 的 `fwidth()` AA 结论、§8 P0 的 `opacity/transform 离屏层` 均为**未落地的早期草案**：当前实现是按需全量光栅 + SDF 固定 1 像素过渡带（见 [Graphics.cpp](../DUI/Graphics/Graphics.cpp) 的着色器注释），transform 走本节的顶点变换、不使用离屏层。

## 9. 结论记录（已定）

1. **后台缓冲格式 = `B8G8R8A8_UNORM`**（gamma 空间混合，非 sRGB RT）：与 DWM/截图/远程桌面管线惯例及 D2D 互操作路径一致；字形 AA 覆盖率由 DWrite 灰度光栅直出，无后处理 LUT。细节见 §5、§6.2。
2. **脏区阈值 = 上限 8 矩形、联合面积 50% 退化全屏**，贪心两两合并即止：MVP 下只影响"进不进帧"的精度，生效于 P2 离屏缓冲方案。细节见 §4.2。
3. **SDF 抗锯齿宽度 = `fwidth()` 自适应**：圆角矩形独立 quad（batcher 约束）；半径 < 1px 在 CPU 收集阶段退化为直角矩形。细节见 §6.2。
4. **层载体 = 独立 render target + 精确尺寸池化（LRU 16）**：层内元素脏整层重绘；嵌套 ≤ 4，Debug 断言。细节见 §3。
5. **显示列表分段缓存的引入指标 = P95 收集耗时 > 0.5 ms 且占当帧 CPU > 15%、连续 100 帧**（双条件缺一不可，统计自 P1 观测面板落地后开始）：为低于 0.5 ms（约帧预算 3%）的工作引入整个渲染子系统里最复杂的改动（第二套失效系统）不值得。细节见 §3。
