# 渲染

> 状态：草案 v0.1 — **渲染主路径已定案**（§9 结论记录）；模糊/阴影、离屏缓冲等 P1/P2 项随实现推进补充。
> 需求来源：保留模式 + 脏区（ADR-005）、按需呈现（"没有失效就没有工作"）、高保真（[12-Windowing.md](./12-Windowing.md) §7.1）、批量化（[00-Overview.md](./00-Overview.md) §3）。
> 相关：[01-Layering.md](./01-Layering.md) §3（帧生命周期）与 Graphics 模块清单、[02-Decisions.md](./02-Decisions.md) ADR-001（D3D11+DXGI）/ ADR-003（字形光栅）/ ADR-005（保留模式）、[03-Style.md](./03-Style.md) §7（失效表）、[05-Animation.md](./05-Animation.md) §7、[12-Windowing.md](./12-Windowing.md)。

## 1. 需求

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| R1 | 按需工作 | 无脏区且无动画时：不收集、不光栅、不 Present，CPU/GPU 归零 |
| R2 | 局部代价 | 改一个颜色只付出"重绘该元素"量级的成本，不触发全窗重排 |
| R3 | 批量化 | Draw Call 数与元素数量解耦；同图集/同材质的矩形合并为尽可能少的批 |
| R4 | 高保真 | 预乘 Alpha 全程一致、描边像素对齐、灰度 AA + gamma 校正（见 [12-Windowing.md](./12-Windowing.md) §7.1） |
| R5 | 热路径零分配 | 收集/排序/顶点生成全程走 Arena 与环形缓冲，无堆分配 |
| R6 | 可裁剪 | 文本/图片/动画关闭后，对应渲染路径不进二进制 |

## 2. 管线总览

与 [01-Layering.md](./01-Layering.md) §3 的帧生命周期对齐，渲染侧的细化数据流：

```
[失效]  属性 / 状态 / 样式 / 布局变更 → 产出脏矩形（帧末合并，见 §4）
   ↓ 有脏区或有活动动画？
[收集]  Arena 重置 → 遍历可见元素树（视口 + 裁剪剔除）→ 显示列表（§3）
   ↓
[排序]  不透明指令按"材质 → 图集"分组前置；半透明指令保持 Z 序（画家算法）
   ↓
[批合并] 同批次写顶点环形缓冲 → 合并为最少 Draw Call（§6）
   ↓
[光栅]  顶点统一乘 scale 矩阵（DIP → 物理像素）→ 片元着色（§6.2）
   ↓
[呈现]  Present（VSync 默认开；本帧无脏区则不调用，见 §5）
```

入口判定"**有没有脏区**"在帧生命周期的最前端：它决定这一帧是否存在，而不是决定这一帧里省多少事（见 §5 的 FLIP 约束）。

## 3. 显示列表

**D1 构建策略：每帧全量重建（已定，MVP）。**

| 方案 | 体 | 复 | 说明 |
| --- | --- | --- | --- |
| **全量重建**（MVP） | ○ | ++ | 有脏区时重置 Arena、遍历整棵可见树重新收集指令；失效模型只有一套（Style/布局的失效表），无第二套缓存失效 |
| 按元素分段缓存 | + | -- | 每元素缓存自己的指令段，脏元素只重建自己的段；省收集，但引入与样式失效正交的第二套失效管理，且段边界与层/裁剪耦合 |

选择依据：收集本身是纯 CPU 内存写，一个 1000 元素的界面全量重建 < 0.1 ms 量级；而分段缓存省下的正是这部分。**用 profile 说话**：只有当 P95 收集耗时 > 0.5 ms、且占当帧 CPU 总耗时 > 15%、连续 100 帧时才立项（双条件缺一不可，判定细节见 §9-5）。

显示列表的内容：

| 指令 | 说明 |
| --- | --- |
| `Rect` / `RoundedRect` | 纯色或渐变填充；圆角在片元着色器内按 SDF 距离裁形（§6.2） |
| `TextRun` | 字形实例（图集坐标 + 位置），来自 Text 层排版结果 |
| `Image` | 图集/纹理引用 + 目标矩形 |
| `PushClip` / `PopClip` | 矩形 / 圆角矩形裁剪（栈式，与 `overflow` 联动） |
| `PushLayer` / `PopLayer` | 离屏层：`opacity < 1` 的子树、带 `transform` 的子树 |

层（`PushLayer`）是渲染里唯一"子树整体先画到离屏再合成"的场合，触发条件收敛为：`opacity < 1`、`transform` 非恒等。其余一律直绘，避免层爆炸。

层载体（已定）：**独立 render target + 精确尺寸池化**。

- 不进图集页：层 bounds 可达整窗大小，会打碎为字形/图标设计的图集布局；且"整层合成后再采样"在图集页上有相邻内容渗色（bleed）问题，无解。
- 池化：按精确 `(宽, 高)` 匹配 + LRU 上限 **16 个**。层 bounds 在动画期间基本稳定，精确匹配命中率远高于 2 的幂档位；超上限淘汰最久未用。
- 失效：层内任何元素脏 → **整层重绘**（不做层内脏区追踪）；层 bounds 变化 → 换 RT。
- 深度防护：层嵌套 ≤ **4**，超出在 Debug 下断言 —— 嵌套过深说明界面结构有问题，应在设计层解决而不是让渲染硬扛。

内存：显示列表、排序缓冲、顶点全部从窗口 Arena 分配，帧末整体重置（[01-Layering.md](./01-Layering.md) §4），热路径零分配（R5）。

## 4. 脏区

脏区的职责在 MVP 下是**决定"这一帧是否存在"以及"将来限定光栅范围"**，不是限定本帧像素更新（原因见 §5）。

### 4.1 产出

每条失效路径换算为一个矩形（03-Style §7 的失效表 → 矩形）：

| 来源 | 矩形 |
| --- | --- |
| `Paint` 类属性变更 / 状态切换 | 元素当前 bounds（含 `transform` 后包围盒） |
| 元素移动 / 消失 / 滚动 | 新旧两个 bounds 的并集 |
| 文本重排版 | 受影响行盒区域 |
| 阴影 / 层 | bounds 外扩（模糊半径 + 偏移） |
| 布局变更 | 受影响子树的联合包围盒 |
| DPI / 用户缩放变化 | 全屏 |

### 4.2 合并

- 帧内先收集后合并：帧末对脏矩形列表做**一次**合并，而不是每次失效都合并。
- 合并规则（已定）：列表上限 **8** 个矩形；插入新矩形时与现有矩形求可合并对（相交/相邻则并）；超过上限或联合面积超过窗口 **50%** → 退化为单一包围盒乃至全屏。
- **贪心两两合并即止，不做最优矩形并**（那是 NP 难题的花样版本）。这两个阈值在 MVP 下只影响"进不进帧"的精度，真正生效于 P2 的离屏缓冲方案；定值原则是够用、可调、实现极简。
- 定值依据：常见交互同时产生约 3–5 个独立脏区（hover 项 + 旧 hover 项 + 提示 + 滚动条）；列表滚动一步就超限退化全屏——这正是期望行为。50% 以上时多 scissor 的状态切换成本开始超过省下的填充。
- 脏区列表本身从 Arena 分配，帧末随 Arena 重置。

## 5. 呈现策略（FLIP 交换链的约束）

**D2 核心结论：MVP 做"按需全量光栅"，不做局部像素更新。**

约束来源：交换链用 Flip Model（`DXGI_SWAP_EFFECT_FLIP_DISCARD`，ADR-001 已定方向），Present 之后后台缓冲内容**未定义**——不能假设上一帧的像素还在，因此不存在"只重绘脏区那几十个像素、其余沿用上帧"的直接做法。`Present1` 的 dirty rects 参数在 FLIP 模型下同样不受支持。

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| **按需全量光栅**（MVP，已定） | 有脏区/动画才进帧；进帧则整窗重新光栅 + Present | 简单、正确；GPU 侧一个中等复杂度界面全屏重绘远低于 1 ms，60 fps 无压力 |
| 持久离屏缓冲 + 脏区更新 + 全屏 blit | 脏区像素更新到一张常驻纹理，再整体拷入后台缓冲 | 省 GPU 光栅，但多一次全屏拷贝 + 常驻显存 + 第二套脏区管理；仅在"全量光栅成为实测瓶颈"时引入（P2） |

这个结论同时回答了 [05-Animation.md](./05-Animation.md) §7.4 遗留的问题——**动画期间不放弃脏区，但也不靠脏区省事**：动画期间 UI ticker 每帧进帧（本来就要全量光栅），脏区继续按 §4 记录，供未来的离屏缓冲方案使用。两条文档由此收敛为同一结论。

与 [12-Windowing.md](./12-Windowing.md) 的衔接：scale 变化（DPI / 用户缩放）走唯一入口 `Window::ApplyScale(scale)` → 交换链 `ResizeBuffers` + 全屏脏区，P2 的用户缩放只是再调一次它。

**后台缓冲格式（已定）：`B8G8R8A8_UNORM`。**

- DWM 合成、截图工具、远程桌面的 Windows 桌面管线以 BGRA 为惯例；保留将来与 Direct2D 互操作的路径（`CreateBitmapFromDxgiSurface` 要求 BGRA）。RGBA8 无补偿性优势。
- 用非 sRGB 的 `UNORM`（gamma 空间混合），理由与代价见 §6.2。

## 6. 批合并与光栅

### 6.1 批合并

- 排序规则：**不透明指令前置**（可按材质/图集自由重排，深度测试无关紧要，目标是减状态切换），**半透明指令保持树序**（画家算法，不可重排）。
- 批的划分：同着色器 + 同图集/纹理 → 一个批；跨批仅在图集切换、层切换、裁剪形态变化处发生。
- 顶点格式：`pos(2×f32) + uv(2×f32) + color(rgba8)` ≈ 20 B/顶点；矩形 4 顶点 + 6 索引，写入环形缓冲，帧末随 Arena 重置。
- 指标：Draw Call 数、批数、顶点数纳入观测（ADR-015：以指标跟踪回归，不设硬门槛）。

### 6.2 片元着色

着色器数量刻意压到极少：

| 着色器 | 覆盖 |
| --- | --- |
| 纯色/渐变 + SDF 圆角 | `Rect` / `RoundedRect`（圆角矩形在片元内按距离场裁形，一次 draw，无 stencil） |
| 图集采样 | 字形（灰度 AA，gamma 校正）、图标、图片 |
| 后续：模糊/阴影 | P1+，阴影先用预烘焙或多次矩形近似 |

像素对齐（[12-Windowing.md](./12-Windowing.md) §7.1-4）在顶点生成阶段完成：描边/分割线类指令的坐标对齐到物理像素网格，文本与大面积填充不做。

**SDF 圆角矩形的抗锯齿（已定）：宽度用 `fwidth()`（屏幕空间导数），不做固定值。**

```hlsl
float w = fwidth(d);                        // 自动随 scale / transform 缩放
float alpha = 1.0f - smoothstep(-w, w, d);
```

- 固定 1 物理像素在 200% 下"过锐"（AA 宽度不足半像素，圆弧出台阶）；固定 1 DIP 在 100% 下"过糊"。`fwidth` 两者皆无，还顺带正确处理 `transform.scale` 动画期间的连续缩放；`fwidth` 是 ps_5_0 标准指令，零额外开销。
- batcher 约束：圆角矩形必须是**独立 4 顶点 quad**（实例化绘制），不得与其他几何共享三角形边 —— `fwidth` 基于 2×2 quad 差分，共享边界会出伪影。批合并本就是矩形流水线，天然满足，成文防回退。
- 例外：圆角半径 < 1px 时退化为直角矩形，该分支在 **CPU 收集阶段**做，不进 shader。

**混合空间（已定）：gamma 空间（非 sRGB render target）。**

- 样式常量按 sRGB 直觉书写，换 sRGB RT 会整体改变配色观感；与 DWM / Direct2D / 主流 Windows UI 框架一致。
- 字形 AA 的 gamma 校正在**图集光栅化阶段**完成（DWrite 光栅参数），管线内不做二次校正。
- 已知代价：gamma 空间的半透明混合数学上不严格（大面积低透明度叠加轻微偏色），全行业 2D UI 的通行取舍；真出现问题时局部换 sRGB RT 是后向兼容的改动。

### 6.3 裁剪

- `Clip` 栈与元素树的 `overflow` 联动：`Hidden` → `PushClip(RoundedRect)`；`Scroll` → 裁剪 + 内容偏移（不重排，04-Layout §6.1）。
- 矩形裁剪优先 scissor（零成本），圆角裁剪走片元 SDF；同一批内裁剪状态一致才可合并。

## 9. 结论记录（已定）

1. **后台缓冲格式 = `B8G8R8A8_UNORM`**（gamma 空间混合，非 sRGB RT）：与 DWM/截图/远程桌面管线惯例及 D2D 互操作路径一致；字形 gamma 校正在图集光栅化阶段完成。细节见 §5、§6.2。
2. **脏区阈值 = 上限 8 矩形、联合面积 50% 退化全屏**，贪心两两合并即止：MVP 下只影响"进不进帧"的精度，生效于 P2 离屏缓冲方案。细节见 §4.2。
3. **SDF 抗锯齿宽度 = `fwidth()` 自适应**：圆角矩形独立 quad（batcher 约束）；半径 < 1px 在 CPU 收集阶段退化为直角矩形。细节见 §6.2。
4. **层载体 = 独立 render target + 精确尺寸池化（LRU 16）**：层内元素脏整层重绘；嵌套 ≤ 4，Debug 断言。细节见 §3。
5. **显示列表分段缓存的引入指标 = P95 收集耗时 > 0.5 ms 且占当帧 CPU > 15%、连续 100 帧**（双条件缺一不可，统计自 P1 观测面板落地后开始）：为低于 0.5 ms（约帧预算 3%）的工作引入整个渲染子系统里最复杂的改动（第二套失效系统）不值得。细节见 §3。
