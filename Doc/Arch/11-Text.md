# 文本：渲染、排版与富文本

> 状态：草案 v0.1 — 待讨论确认。
> 需求来源：① 文字渲染、排版能力**尽可能丰富**；② 框架将来要提供**富文本编辑器控件**（类似 Web 的所见即所得编辑器）。
> 相关：ADR-003（字形光栅化）、ADR-004（排版基座，本文确认并细化）、[06-Events.md](./06-Events.md)（`TextInput / Composition` 事件）、[04-Layout.md](./04-Layout.md) §4.4（内联混排分工）。

## 1. 需求

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| R1 | 渲染丰富 | 多字体混排、颜色文字、下划线/删除线、OpenType 特性（连字等）、灰度 AA（子像素见 §6） |
| R2 | 排版丰富 | 自动换行（词/字/断字）、两端对齐、字距/行距/段落间距、缩进、双向文本（BiDi）、复杂脚本、字体回退 |
| R3 | 富文本 | 同一段落字符级多样式、段落级样式、**内联对象**（图片、控件嵌入文本流） |
| R4 | 富文本编辑器 | 所见即所得：光标、选区、IME、撤销/重做、剪贴板、格式命令（加粗/对齐…），排版结果即编辑显示（无独立预览） |
| R5 | 性能 | 输入低延迟、大文档流畅（段落虚拟化 + 增量失效）、测量缓存 |

### 1.1 约束（沿用既定决策）

- 无异常（ADR-007 已定）、无 RTTI（草案）；错误经 `Result<T>`。
- 热路径零分配：排版结果与字形走缓存/竞技场（[01-Layering.md](./01-Layering.md) §4）。
- 底层为 DirectWrite，不自带字体解析（ADR-004 技术栈前提）。
- 内部单位 DIP（ADR-014）；字形按 (字体, 像素尺寸) 离散缓存（ADR-003 已定）。

## 2. 能力分层（核心结构）

```
L3  编辑器控件        光标/选区/编辑命令/撤销/IME/剪贴板          UI.Widgets（RichEdit）
L2  富文本文档模型    属性区间 + 内联对象；文档 = 段落数组          Text.RichText（数据，可序列化）
L1  排版与渲染引擎    字体集合/成形/段落排版/光栅化/命中测试         Text（无状态服务）
```

- **L1 无状态**：输入文本 + 样式参数 → 排版结果 + 绘制指令，可独立测试、可裁剪（`DUI_ENABLE_TEXT`）。
- **L2 是数据**：文档模型可序列化、可脱离 UI 存在；渲染时翻译为 L1 调用。
- **L3 是交互**：在 L2 之上加编辑行为；控件只是 L2 的一个"视图 + 控制器"。

**控件阶梯**（对应 00-Overview 能力清单）：

| 控件 | 依赖层 | 说明 |
| --- | --- | --- |
| `Label` | L1 | 单一样式静态文本 |
| `TextBlock` | L2 | 富样式只读（多 run + 内联对象） |
| `TextBox` | L1 + 编辑基元 | 纯文本单行/多行编辑（IME、选区、复制粘贴、撤销） |
| `RichEdit` | L2 + L3 | 所见即所得富文本编辑器（**长期目标**） |

> 分层的意义：RichEdit 控件可以后做，但 L1 的能力清单和 L2 的数据结构**从现在起按本文档预留**，避免返工。

## 3. L1：排版与渲染引擎（确认并细化 ADR-004）

**确认：IDWriteTextLayout 直接用**，使用粒度为**段落**：

- 一个段落 = 一个 `IDWriteTextLayout` 实例，按段落缓存、按需失效（内容/样式/宽度变化才重建）。
- 免费获得：换行、BiDi、复杂脚本、字体回退、命中测试（`HitTest*` API）、内联对象（`IDWriteInlineObject`）、OpenType 特性（`SetTypographicStyle`）。
- 热路径：段落级测量缓存 + 字形图集（ADR-003），输入场景只失效被编辑段落。
- 自排（`IDWriteTextAnalyzer`）仍按 ADR-004 保留为瓶颈后备，不预做。

**能力与实现方式对照**：

| 能力 | 方式 | 备注 |
| --- | --- | --- |
| 换行策略（词/字/任意） | DWrite `wordWrapping` | 断字（hyphenation）P2 |
| 两端对齐 | DWrite `DWRITE_TEXT_ALIGNMENT_JUSTIFIED` | 基线 Win10 1703 可用 |
| 字符间距 | `IDWriteTextLayout1::SetCharacterSpacing` | 对应 03-Style `letterSpacing` |
| 行距（等高/比例/最小） | `IDWriteTextLayout3::SetLineSpacing` | 对应 03-Style `lineHeight` |
| 下划线/删除线 | `SetUnderline` / `SetStrikethrough` + 绘制回调 | |
| 字符级样式（颜色等） | `SetDrawingEffect` + 自定义绘制回调 | 富文本 run 的落点 |
| BiDi / 复杂脚本 / 回退 | DWrite 内建 | |
| 描边文字、渐变文字 | 自定义绘制回调 + Graphics 层 | P2，走 03-Style `color` 的扩展形态 |

## 4. L2：富文本文档模型

```
Document  = 段落数组
Paragraph = 文本缓冲（UTF-16，与 DWrite 零转换）
          + 字符属性区间表（run 列表）
          + 内联对象表（图片/控件，占一个"对象字符"位）
          + 段落级样式（对齐/行距/缩进/间距/方向）
```

- **字符样式属性集**：字体、字号、字重、斜体、颜色、下划线、删除线、**背景高亮**、字距、**链接**（已拍板：核心可支持的均列入目标；上下标需自实现，先不实现，见 §9）。
- **编辑数据结构**：MVP 用 run 数组（段落内有序区间），实现简单、够用；大文档性能瓶颈出现再换 piece table（D2）。
- **内联对象**：实现 `IDWriteInlineObject` 适配器接入 L1；占位字符参与换行与命中测试 —— 对应 [04-Layout.md](./04-Layout.md) §4.4 的"行内混排归文本排版"，两侧在此接合。
- **序列化**：内部格式（二进制/JSON）P2；剪贴板见 D4。
- **编码**：模型内部与对外 API 统一 **UTF-16**（DWrite / Win32 W API 原生，零转码），字面量用 `L"..."`；UTF-8 仅出现在文件/网络/剪贴板等外部边界，经显式转换（ADR-026）。所有文本位置与范围均以 **UTF-16 code unit** 计，与 `DWRITE_TEXT_RANGE` 一一对应 —— 这是选区、命中测试、撤销栈的前提。

### 4.1 富文本属性与样式系统的关系（重要，D3）

富文本的字符/段落属性是**内容属性**（属于文档数据，随文本复制、粘贴、序列化），**不进** [03-Style.md](./03-Style.md) 的元素样式系统：

- 样式系统管"元素外观"（这个 `TextBlock` 控件多大、什么字体回退策略）；
- 文档模型管"内容长什么样"（这一段字是红色、那段是 18 号）。

衔接点：文档的**默认样式**（新输入字符的格式、未显式设置 run 样式时的兜底）由所在元素的样式提供（`fontSize` / `fontFamily` 等注入文档默认值）——主题换字体，富文本默认外观跟着变，但已显式设置的内容样式不受影响。

## 5. L3：编辑器控件（所见即所得）

- **渲染即编辑**：编辑显示直接走 L1 排版结果，无独立预览路径（R4"所见即所得"的实现含义）。
- **光标**：闪烁由动画系统驱动（[05-Animation.md](./05-Animation.md)）；光标位置 ↔ 字符索引用 L1 命中测试互转。
- **选区**：拖拽、双击选词、三击选段、`Shift+方向键` 扩展；跨段落选区为编辑器内置（不依赖 [06-Events.md](./06-Events.md) 的"文本选择完整程度"悬案——见 ADR-017）。
- **IME**：组合串内联渲染（composition 下划线样式）+ 候选窗定位（Platform.Ime）；事件入口为 `TextInput / Composition*`（[06-Events.md](./06-Events.md) §3）。
- **撤销/重做**：命令栈 + 打字合并窗口（连续输入合并为一步）；撤销粒度为段落内操作。
- **格式命令**：`SetSelectionBold()` / `SetSelectionColor()` / `SetAlignment()` 等 —— 所见即所得工具栏的对接点；`OnSelectionChanged` / `OnTextChanged` 语义事件（[06-Events.md](./06-Events.md) §3）。
- **大文档**：段落虚拟化 —— 只排版/绘制可见段落，与 [04-Layout.md](./04-Layout.md) 的列表虚拟化同一机制。

## 6. 渲染质量

- **AA**：MVP 灰度（ADR-003 已定方向：子像素与任意合成冲突）；ClearType 作为待定项保留在 ADR-003。
- **可变字体**：DWrite 有部分支持（Win10 1703 起），列为能力待定，不进 MVP。
- **超大字号**：轮廓退化路径（ADR-003 已定）。

## 7. 决策点

### D1 排版基座（确认 ADR-004）
IDWriteTextLayout 段落级使用 + 段落缓存/失效。ADR-004 原为"建议"，随本文档**建议一并拍板**。

### D2 编辑数据结构：run 数组（MVP）→ piece table（P2）
简单优先；性能问题出现（超大单段落、高频编辑）再迁移，接口（L2 API）不变。

### D3 富文本属性不进样式系统
见 §4.1。内容属性与元素样式分离；默认值注入是唯一衔接点。

### D4 剪贴板与序列化范围
MVP：`CF_UNICODETEXT`（纯文本）；内部序列化 P2；**HTML / RTF 导入导出列 P2 且可裁剪**（HTML 解析体积可观，与"体积小"权衡；做成独立模块，不用不链接）。

### D5 RichEdit 排期：控件 P2，能力预留从现在开始
用户需求为"将来提供"——本文档的分层就是预留方案：L1 能力清单（§3）与 L2 数据结构（§4）按编辑器需求设计，L3 控件后置。
